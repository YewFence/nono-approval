# Leave same-UID control isolation to deployment

The MVP keeps the owner-only control socket and peer-UID checks but does not add a bearer token, generate mandatory nono profiles, or wrap Agent launches. Users who require protection from a sandboxed Agent connecting to the control socket must configure nono pathname AF_UNIX mediation on Linux or a restricted network mode on macOS and avoid grants that cover the control socket. `nono-approval config validate --profile <name-or-path>` starts a short-lived real sandbox and passes only when an in-sandbox probe is confirmed to have started and its control-socket connection is denied with `EACCES` or `EPERM`; the probe uses only the stateless status API and never creates or decides an approval request. Validation is explicit rather than installed as a session after hook because hooks run with host privileges, execute after the risk window, are replaceable by child profiles, and would make same-profile probing recursive. Running the real profile may execute its existing host-side session hooks once, which the command must disclose. The project does not guarantee that validation is executed before a later launch or that the same profile is used, keeping same-UID isolation an explicit deployment responsibility.
